## 1. 测试目标

围绕 AI 心理健康助手 V1.0 的 4 个核心业务模块展开，目标如下：

| 维度 | 目标 |
|------|------|
| **功能正确性** | 验证核心模块功能是否与需求文档一致 |
| **流式交互稳定性** | 验证 SSE 流式对话在正常、中断、超时场景下的表现 |
| **权限隔离有效性** | 验证前台/后台 userType 双端路由隔离是否生效 |
| **边界与异常容错** | 验证评分边界、非法输入、网络异常下的系统表现 |
| **易用性** | 验证提示信息、交互反馈是否符合用户预期 |

> 📌 **简历定位说明**：本项目为纯前端工程，后端由课程方部署维护，测试为**黑盒功能测试 + 接口测试**实践。与若依（通用后台框架）形成差异化：本项目聚焦业务场景 + 新型前端交互（SSE 流式、双端权限、富文本、情绪评分）。

## 3. 测试策略

### 3.1 测试类型与执行方式

| 测试类型 | 执行方式 | 占比 | 说明 |
|----------|----------|------|------|
| 功能测试 | 手工黑盒 | 70% | 覆盖核心模块正向/逆向/边界/异常 |
| 接口测试 | 浏览器 Network + Postman 手工调试 | 15% | 验证关键接口输入输出、状态码、响应结构 |
| UI 测试 | 手工走查 | 8% | 页面布局、提示信息、交互反馈 |
| 兼容性测试 | 手工，Chrome + Edge | 5% | 两大浏览器核心流程回归 |
| 安全性测试 | 手工，结合功能测试 | 2% | 越权访问、XSS 输入、Token 伪造探索性测试 |

### 3.2 测试方法

| 方法 | 适用场景 | 说明 |
|------|----------|------|
| 场景法 | 所有模块 | 模拟真实业务流，如"注册→登录→发起咨询→情绪分析" |
| 等价类划分 | 输入型功能 | 邮箱格式、密码长度、评分区间 |
| 边界值分析 | 数值/长度输入 | 情绪评分 1 与 10、密码长度边界 |
| 错误推测法 | 逆向/异常 | 断网、超时、特殊字符、越权路径 |
| 探索性测试 | AI 对话、富文本 | 开放式输入：超长文本、敏感词、极端情绪语句、XSS 脚本 |

### 3.3 SSE 流式接口专项策略（本项目特色）

| 测试点 | 方法 | 验证目标 |
|--------|------|----------|
| 流式分段到达 | 浏览器 Network 观察 EventStream | 回复分片持续推送，打字机渲染 |
| 流式中断 | 断网 / 关闭请求 | 是否卡死、是否有重连或提示 |
| 超时处理 | 模拟后端无响应（5000ms） | 是否友好提示，而非白屏 |
| 响应类型校验 | 观察响应 Content-Type | 非 text/event-stream 时是否报错 |

### 4.3 测试数据

- **后端**：课程方统一部署的外部服务，**无法直接查数据库**，测试为黑盒。
- **测试账号准备**：
  - 前台普通用户：测试前自行注册（`/auth/register`），建议账号加 `test_` 前缀。

- **数据污染风险**：后端为共享服务，数据可能被他人改动，执行前记录初始状态，执行后尽量清理测试数据（如删除自建文章、会话）。

## 7. 缺陷管理规范

### 7.1 缺陷等级定义

| 等级 | 名称 | 定义 | 响应要求 |
|------|------|------|----------|
| **A-致命** | 系统崩溃/数据丢失 | 页面崩溃、越权导致敏感数据泄露 | 必须修复 |
| **B-严重** | 核心功能不可用 | P0 模块主流程无法完成 | 必须修复 |
| **C-一般** | 功能异常但有替代 | 边界处理不当、提示不准确 | 建议修复 |
| **D-轻微** | 体验/界面问题 | 排版错乱、文案问题、非关键提示缺失 | 可延后修复 |
| **E-建议** | 优化建议 | 交互体验、性能优化建议 | 非缺陷 |

### 7.2 缺陷报告模板

```
【缺陷ID】BUG-001
【缺陷标题】【模块名】简短描述问题现象
【严重等级】A/B/C/D/E
【发现版本】V1.0
【测试环境】Win11 + Chrome 最新版
【前置条件】已登录前台普通用户
【重现步骤】
  1. 进入咨询页
  2. 断网后发送消息
【实际结果】页面无响应且无错误提示
【预期结果】应提示"网络异常，请重试"或自动重连
【复现频率】必现
【附件】截图/录屏
【备注】—
```

## 8. 风险管理

| 序号 | 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|------|----------|
| R1 | 后端为外部共享服务，数据被他人改动影响用例复现 | 高 | 高 | 执行前记录初始状态，测试数据加 `test_` 前缀，执行后清理 |
| R2 | 后端不稳定/重启，导致接口临时不可用 | 中 | 高 | 失败用例先区分"环境问题"还是"缺陷"，环境问题标记 Blocked |
| R3 | 管理员账号权限不明，权限隔离用例无法完整验证 | 中 | 高 | 优先用前台普通账号验证越权拦截；管理员账号不明确时记录为 Blocked |
| R4 | 无法查数据库，接口"是否真正落库"无法验证 | 高 | 中 | 改为验证"接口返回 + 前端刷新后可见"，明确为黑盒测试结论 |
| R5 | SSE 流式接口用普通工具难验证 | 中 | 中 | 用浏览器 Network 面板观察 EventStream，配合断网模拟 |
| R6 | 响应码为字符串 `"200"`，断言/理解易出错 | 中 | 低 | 接口测试中明确区分字符串与数字，从源码确认约定 |
