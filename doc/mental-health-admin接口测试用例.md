## 测试约定

| 约定 | 说明 |
|------|------|
| 接口地址 | 后端真实地址带 `/api` 前缀，如 `http://159.75.169.224:1235/api/user/login` |
| 认证方式 | 请求头字段名 `token`（非 `Authorization`）；登录成功取 `data.token` |
| 成功业务 code | 字符串 `"200"`（非数字） |
| 失败业务 code | 字符串 `"BUSINESS_ERROR"`（业务错误，如"用户不存在"）或 `"-1"`（登录过期）；断言统一用 `!= "200"` |
| HTTP 状态码 | 正常/业务异常通常 `200`；鉴权失败（无 token）通常 `403`；**登出接口例外**（BUG-006 无鉴权，返回 200） |
| 响应结构 | `{ code, msg, data }` |

## 执行说明

1. **「不存在 id」类用例（9 条）是重点**：对应若依发现的「查询不存在资源返回空指针 500」BUG，验证后端对不存在资源的容错。

2. **缺陷回归类用例**：IF_USER_007（BUG-001）、IF_DIARY_002/003（BUG-004）、IF_ARTICLE_006/007（BUG-005），断言直接对应当前已知缺陷，自动化跑通即验证修复。

3. **鉴权类用例（无 token，6 条）**：验证后端接口鉴权是否独立于前端，这是功能测试点不到的场景。

4. **预期状态码「401或200」的处理**：首轮执行时，无 token 的接口若返回 HTTP 401 则预期状态码填 401；若返回 200 + code"-1" 则填 200。跑通一次后把表格里「401或200」统一校准为实际值。

5. **优先实现顺序**：用户接口（拿 token 是前提）→ 情绪日记 → 知识文章 → 心理咨询。
